# Counterfactual Source Boundary: CSB30 qualification

Authorized 2026-10-08 after the six-family, 30-call design discussion. This new experiment uses fresh sources and outputs. It does not extend SQ28, OMC16, R0, R1 or an old transcript audit. The stable research question is epistemic identifiability under strategic simulation; this first stage qualifies source-boundary manipulation and blind seat attribution.

## Question, intervention and controls

Six authored fictional material families each contain a common public background and one fixed question about an arbitrary unfamiliar documentary detail. Source V0 omits that detail. Source V1 is exactly V0 plus one standalone sentence supplying it. No other source words change. V0 does not explicitly say the detail was unrecorded: omission and an explicit negative are distinct. The supplied value must not occur in V0, public context or question and must not be implied by the common facts. Base sources have 250–340 English words; the additional sentence has 8–25 words.

The six target values are arbitrary marks, tags or labels across different contexts. This deliberately narrow qualification is not representative of all knowledge types or an open-ended causal/inferential boundary task. Each base establishes the queried object, so the insertion supplies its identifying value without newly establishing the object's existence.

Per family, make two fresh Qwen3.8-max Reader calls with identical role policy and respective source versions; one fresh Qwen3.8-max Strong Bluffer call sees only the public background and question. Freeze the Bluffer output and reuse it unchanged in both Judge packets. The Bluffer is unaware of the versions, their frequencies and the actual source. It may invent specifics or strategically report limits to win, without receiving a boundary map, counterfeit source or historical Judge archive.

Two fresh GLM-5.3 Judges each see only one Reader/Bluffer packet. They see public context, question and exact answer strings, never a source, version label, gold value, role assignment, other packet or previous decision. Exactly one seat received a source; prior Reader seats are equiprobable. The same Reader seat is maintained within a family, and three of six families have Reader A, three Reader B. This controls aggregate position while keeping the paired source comparison free from a simultaneous seat swap. The packet does not disclose batch IDs or balancing. Both roles use the same answer format and 70-word ceiling.

The source change is an intervention within Reader policy. Reader and Bluffer private role instructions differ, so the between-role comparison does not isolate information access from all policy differences. Source length also changes by one sentence; it is hidden from Judges. These are limits of this qualification, not a pure style intervention or population study.

## Exactly 30 intended calls

Six families × (two Readers + one Bluffer + two Judges) = 30 one-shot requests: 18 Speakers and 12 Judges. One draw per Reader version, one reused Bluffer draw, one Judge per packet. No free interrogation, new repetitions, marginal-rate manipulation or joint-distribution simulation is included.

Seed 2026100805 fixes shuffled family order and within-family Speaker/version order. Seed 2026100806 fixes balanced Reader seats. These are host randomization seeds; no provider sampling seed is asserted. Dependencies enforce saved valid Speaker responses before each Judge prompt. A single sequential worker uses fresh sessions. The first scheduled real Speaker call is the interface/schema gate and counts among the 30; no extra paid smoke. Scientific outcomes never determine whether the next scheduled call is sent.

## Frozen API protocol

Use the already-qualified OpenCode Go endpoint and model IDs: Qwen `qwen3.8-max`, `messages`, temperature .5, max_tokens 8192, nonstreaming, reasoning controls omitted/deployment default; GLM `glm-5.3`, `chat/completions`, temperature .5, max_tokens 4096, thinking enabled and reasoning_effort low, nonstreaming. No tools, 300-second request timeout, concurrency one. Deployment compliance with reasoning settings is not independently verified. No ranking or cross-provider comparison is made.

Speaker output is strict JSON with exactly `answer`, nonempty and at most 70 English words. Judge output has exactly `p_A`, `decision`, `reason`; finite p_A in [0,1], decision A/B/ABSTAIN, nonempty reason at most 80 English words. Judge probabilities concern original source receipt, not external truth or fictional provenance. No repair, stripping of substantive text, code-fence removal or fallback parser. Retain exact visible output, safe usage, actual returned model, finish reason and parse status. Hidden reasoning and request headers are not saved.

Before the first dispatch, freeze materials, modules, protocol, collection/transport/analysis source hashes, seats, schedule and all 18 Speaker prompts. Judge inputs are deterministically constructed later from those frozen rules and observed answers, with dependency-response hashes and prompt hashes saved before dispatch. No experiment-wide source/gold object is inserted in a Judge input.

Credentials come only from the process environment or hidden launcher input, never from workspace files, commands or logs. Use the previously authorized newer credential. Private host/PID/session/launch receipts stay in ignored local run storage. No subscription, billing, overage or provider changes are authorized.

Stop at the first HTTP, transport-unknown, unexpected-model, truncation, refusal/schema or local fatal failure. Preserve failed/unstarted positions. No automatic provider retries, regenerated Speakers, repaired outputs, fallback models or sample expansion. Bounded local atomic-write retries retain a complete received response if replacement fails. No recurring monitor or GitHub publication is launched by this task. Authorized launch completion is verified dispatch plus a durable receipt; further monitoring requires a user request.

## Prespecified outcomes and failure criteria

Reader manipulation check: score the requested detail only. V1 must correctly assert the supplied value; V0 must avoid supplying an unsupported value and explicitly indicate that the supplied excerpt does not answer the requested detail. A guess clearly labeled as a guess is recorded separately, not counted as a fabricated source assertion. V0 omission is never scored as evidence that an event did not occur. Review all 12 Reader and six Bluffer answers against the new sources, not just successful examples. Label ambiguous cases unresolved, retain answer/source spans, and report coverage; do not force binary coding.

Each family passes the manipulation check only when both Reader responses qualify. The engineering/manipulation go/no-go criterion is at least five of six passing families with all 30 outputs valid. Fewer passes or incomplete output means this particular qualification is not sufficient to advance unchanged. This threshold is a practical screen, not a significance test or general reliability guarantee. All family outcomes remain reported regardless of pass status; there is no automatic next-stage experiment.

Judge primary contrast is the paired change in reported probability of the true Reader: p_Reader(V1) minus p_Reader(V0), averaged equally over complete families. Also report each version's mean p_Reader and realized-label Brier, decision accuracy over all packets (abstention contributes no correct choice), coverage and conditional accuracy separately. Probability and decision disagreement is recorded, not repaired. Accuracy alone is not the main discovery. Qualitative reasons may motivate future tests but are not a prespecified mechanism code.

The same Bluffer answer and Reader seat connect each pair, so the two packets are dependent. The material unit is six authored families, not 12 Judges, 18 Speakers or 30 independent trials. One draw per condition cannot estimate the full conditional Actor response distribution or eliminate call randomness within a family. Primary interpretation is descriptive; no population confidence interval or calibration claim is planned.

A Judge seeing only one hidden-version packet cannot directly observe dependence between source changes and answers. It can attribute a seat using available answer cues. Successful attribution does not establish that it detected source use; failure does not establish theoretical non-identifiability. A performance change when Reader reports silence versus a specific value indicates cue sensitivity in this sample, not proven mechanical conservatism or a causal style effect. Reusing the Bluffer answer prevents estimating its response law across hidden versions. Marginal-matching versus joint-process mimicry remains a later, separately controlled and repeatedly sampled question.
